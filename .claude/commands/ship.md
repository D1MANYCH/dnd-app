argument-hint: [patch|minor|major] ["<changelog>"] [--no-post]
---
Аргументы: `$ARGUMENTS` — **все необязательные**. Пустой вызов означает «разберись сам
и выпусти». Ничего не переспрашивать: запуск команды и есть разрешение на коммит и пуш.

## 1. Понять, что выпускаем

`git status --porcelain`, `git diff --stat HEAD`, при неясности — сам diff по файлам.

- Дерево чистое и `HEAD` не опережает `origin/main` → «выпускать нечего», остановиться.
- Затронуты файлы приложения (js/css/html в корне, `sw.js`, `manifest.json`, `assets/`)
  → **релиз с bump**.
- Затронуты только `.claude/`, `tools/`, `tests/`, `docs/`, `README.md`, `CLAUDE.md`
  → **коммит без bump**: версию поднимать не за что, пользователи ничего не увидят.

## 2. Определить уровень и текст (если не заданы аргументами)

- Уровень: новая пользовательская возможность → `minor`; исправление, доработка,
  контент, данные → `patch`. **`major` автоматически никогда** — только если задан явно.
- Текст changelog пишется по diff: что изменилось, числа, имена механик, значения.
  Тон = changelog, без эпитетов, рекламы и упоминаний продвижения.
- `--type`: `feat` / `fix` / `chore` по сути правки.
- Выбранное не согласовывать заранее — показать в итоговом отчёте.

## 3. Запустить `releaser` синхронно (`run_in_background: false`)

Передать: режим (релиз с bump / коммит без bump), уровень, дословный текст changelog,
`--type`, и явно — «коммит и пуш разрешены, после пуша дождаться CI».

Отчёт агента показать как есть. Если он остановился (красные тесты, посторонние коммиты
в `origin`, красный CI) — дальше не идти, доложить причину и что делать.

## 4. Пост

Только для релиза с bump и если нет `--no-post`: запустить `relpost` синхронно с номером
выпущенной версии и `--out`-слагом по сути релиза.

Текст поста **не вставлять внутрь блока хвостов** — он печатается последним, отдельным
блоком, целиком и готовым к копированию. Коммит без bump — поста нет и в хвостах он
не упоминается.

## 5. Итог — три блока, печатать ПЕРЕД текстом поста

```
Готово: v3.60.1 · chore(dev): … · e25e6d2 · tests ✅ pages ✅

Хвосты:
- Пост не опубликован — текст ниже, публикуешь ты
- app-spells.js менялся, но в preview не проверялся
- Фаза SUB-4 в memory не отмечена done

Дальше: /done SUB-4, затем можно брать SUB-5
```

Хвосты искать среди: незакоммиченные файлы после пуша; правка js/css не проверялась
в preview; активная фаза плана не закрыта (`/done X-N`); итог фазы не записан в memory;
предупреждения warn-хуков (упавшие тесты, рост хардкодов темы); CI красный или проверить
не удалось; пост не опубликован (пишется всегда — публикует пользователь).
Хвостов нет — так и написать: «Хвосты: нет».
