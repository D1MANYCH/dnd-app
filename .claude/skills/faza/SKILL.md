# Работа над фазой: процедура

Точки входа — команды `/phase X-N` (старт, читает блок фазы из memory) и `/done X-N`
(закрытие статуса). Этот скилл описывает, что делается **между** ними.

## 1. Ветка

До первой правки: `git checkout main && git pull` → `git checkout -b phase-N-имя`
(имя короткое, по сути фазы: `phase-2-syntax-hook`, `phase-3-faza`).
В `main` не работать. Ветка живёт до конца фазы, вливается fast-forward'ом.

## 2. План — до правок

Формат: **файл → функция → что меняем**, одной таблицей или списком, без кода.
Показать пользователю и дождаться одобрения. Пока не одобрено — ничего не менять,
включая «очевидные» мелочи.

Неоднозначность в задании (цифры правил, имена файлов, границы фазы) — **спросить**,
не додумывать. Для контента D&D эталон — книги 2014, выдумывать значения нельзя.

## 3. Работа по пунктам

- Один пункт → показать результат → дождаться подтверждения → следующий.
- Правки точечные (Edit), файлы целиком не переписывать.
- Комментарии в код не добавлять, сверх задачи не рефакторить.
- Существующие файлы править, а не создавать заново рядом.
- Новый js/css-файл = `<script src>`/`loadScript` в `index.html` + `?v=` токен +
  строка в `FILES_TO_CACHE` (`sw.js`).

## 4. Хуки сработают сами

На каждый Edit/Write/MultiEdit (`.claude/settings.json`, PostToolUse):

| Хук | Поведение |
|---|---|
| `tools/check-sw-hook.js` | `sw.js` без бампа `CACHE_NAME` (сверка с HEAD) — **exit 2** |
| version-sync (инлайн) | `APP_VERSION` ≠ `APP_CHANGELOG[0].version` в `data.js` — **exit 2** |
| `tools/run-tests-hook.js` | тесты на правку `*.js` — warn |
| `tools/check-theme.js --hook` | `style.css` — warn |
| `tools/check-syntax-hook.js` | `node --check` на `*.js` — **exit 2** |

exit 2 = правка отклонена, файл не изменён: чинить причину, а не обходить хук.
Вывод warn-хуков читать — там падения тестов и рост хардкодов в теме.

## 5. Проверка перед сдачей

- `/test` — node-тесты, должны быть зелёные (базлайн не ронять).
- Превью: `preview_start {name:"dnd-app"}` (порт 3017), консоль через
  `read_console_messages`. Ловушки — SW отдаёт старый код, скриншот виснет
  на WebGL — скилл **`verify-ui`**, читать ДО проверки.
- Трогали классы/подклассы/билды — `verifyAllBuilds()` в консоли DevTools.
- Verify-критерий фазы берётся из её блока в плане, цифры (тесты, строки, ссылки)
  фиксируются в отчёте.

## 6. Сдача

- Коммит — **только по явному запросу пользователя**. Формат `тип(scope): описание`
  на русском (`feat`/`fix`/`chore`), релиз — с префиксом `vX.Y.Z:`.
- Менялся js/css → это релиз: скилл **`release`** (`/bump` → `/preflight`), версии
  руками не править.
- Влить ветку в `main` fast-forward'ом, merge-коммит не делать, push по запросу.

## 7. Закрытие

`/done X-N`, следом — итог фазы в `project_*_plan.md` (memory): что сделано, находки,
verify-цифры, влияние на следующие фазы. Исходную постановку фазы не стирать —
она остаётся ниже итога для сверки.

## Связанные скиллы (читать ДО задачи, а не после)

`release` — коммит/бамп/push. `verify-ui` — проверка в браузере.
`add-content` — контент D&D (заклинания, классы, предметы, черты).
`dice-3d`, `tours` — при правках бросков и обучения.
