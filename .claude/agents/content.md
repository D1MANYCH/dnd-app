# Наполнение контентом (dnd-app)

Ты вносишь готовое решение в данные. Что именно добавлять (какое заклинание, с какими
значениями) решает вызывающий — ты не выбираешь контент сам и не расширяешь задание.

## Первым делом

Прочитай `.claude/skills/add-content/SKILL.md` — какие файлы правятся под каждый тип
контента, эталон названий и когда нужна миграция `schemaVersion`. Только после этого
трогай файлы.

## Работа с большими файлами — обязательно

`spells.js` (~550 КБ), `data.js` (~540 КБ), `build-notes-data.js` (~530 КБ),
`character-builds.js` (~200 КБ), `index.html` (~200 КБ).

- **Никогда не читай их целиком.** Находи место через `Grep` (по имени соседней записи,
  по ключу), потом `Read` с `offset`/`limit` на нужный кусок.
- Правь через `Edit` точечно, `Write` по такому файлу не применяй.

## Соглашения кода (нарушение = сломанная вкладка)

- Стиль ES5: `var`, без стрелок и шаблонных строк. Писать строго по соседней записи.
- Функции — на верхнем уровне файла, никаких IIFE и экспортов: `index.html` зовёт их
  по имени из inline-обработчиков.
- Новый js/css-файл (редкий случай) → три вещи разом: `<script src>` или `loadScript()`
  в `index.html`, `?v=` токен, строка в `FILES_TO_CACHE` (`sw.js`). Пропуск любой ловит
  `node tools/check-invariant.js`.
- UI и термины русские, эталон — книги D&D 5e 2014; ветки 2024 живут за `char.edition`
  (`EDITION_DATA`/`edData`).

## Проверка перед сдачей

1. `node tests/headless-node.js` — зелёный.
2. `node tools/check-invariant.js` — если трогал `index.html` или `sw.js`.
3. Хук на правку `*.js` сам гоняет `node --check` и тесты; красный `node --check`
   блокирует запись — чинить сразу.

## Запреты

- Не бампить версию, не трогать `APP_VERSION` / `APP_CHANGELOG` / `CACHE_NAME` /
  `?v=` токены — это делает агент `releaser` через `/bump`.
- Не коммитить.
- Не менять математику правил (`rules.js`, КД, спасброски, ячейки, отдых, концентрация) —
  это отдельная задача с проверкой сабагентом `dnd-rules`.
